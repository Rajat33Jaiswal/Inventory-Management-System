# StockSphere - Containerized Inventory & Order Management System

StockSphere is a modern, production-ready, full-stack Inventory & Order Management System designed for businesses to manage their Products catalog, Customer listings, and Transactions.

The system features:
- **FastAPI Backend (Python)**: Provides a validated, high-performance database-driven REST API, with automated Swagger docs and transaction-safe operations.
- **React Frontend (Vite)**: Features a beautiful, high-fidelity responsive dashboard with light/dark modes, real-time counters, transaction receipt inspection, and interactive product, customer, and order builders.
- **PostgreSQL Database**: Serves as the central transaction-safe storage.
- **Docker Compose**: Orchestrates all services for one-command local setups.

## 📦 Local Setup with Docker Compose

Running the entire suite locally requires only [Docker](https://www.docker.com/) and [Docker Compose](https://docs.docker.com/compose/) installed.

1. **Clone & Open Project Directory**:
   ```bash
   cd Inventory_Management_System
   ```

2. **Configure Environment Variables**:
   Copy the example environment file and adjust variables if needed:
   ```bash
   cp .env.example .env
   ```

3. **Spin Up Services**:
   Run Docker Compose to build and start the PostgreSQL database, FastAPI API, and React client:
   ```bash
   docker compose up --build -d
   ```

4. **Verify Application Ports**:
   - **Frontend App**: Access `http://localhost:3000` in your web browser.
   - **Backend API Docs (Swagger)**: Access `http://localhost:8000/docs` to test endpoints manually.
   - **PostgreSQL DB**: Listens on `localhost:5432` (accessible using any database tool like DBeaver or pgAdmin).

5. **Stop Services**:
   ```bash
   docker compose down -v
   ```

## 🛠️ Step-by-Step Deployment Guide

Follow these instructions to deploy StockSphere online using free tiers:

### 1. Version Control (GitHub)
Initialize Git and push your repository to GitHub:
```bash
git init
git add .
git commit -m "feat: initial commit of inventory management system"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
git push -u origin main
```

### 2. Push Backend Image to Docker Hub
Build and publish your production-ready backend image:
```bash
# 1. Login to Docker Hub
docker login

# 2. Build the backend image
docker build -t YOUR_DOCKER_USERNAME/inventory-backend:latest ./backend

# 3. Push to Docker Hub registry
docker push YOUR_DOCKER_USERNAME/inventory-backend:latest
```

### 3. Deploy Backend API & PostgreSQL (Render / Railway)
To deploy the backend on **Render**:
1. Sign in to [Render](https://render.com/).
2. Create a new **PostgreSQL Database** instance.
   - Note the **Internal Database URL** (for backend communication) and **External Database URL** (for database inspection).
3. Create a new **Web Service**:
   - Connect it to your GitHub repository.
   - Select the `backend` folder as the **Root Directory**.
   - Select **Docker** as the Runtime (Render will automatically detect the `Dockerfile` inside the root).
   - Add the following **Environment Variables**:
     - `DATABASE_URL`: Set this to your Render PostgreSQL **Internal Database URL** (e.g. `postgresql://user:pass@host/db`).
     - `PYTHONUNBUFFERED`: `1`
4. Copy the public URL generated by Render once it builds successfully (e.g. `https://inventory-backend.onrender.com`).

### 4. Deploy Frontend Web App (Vercel / Netlify)
To deploy the frontend React SPA on **Vercel**:
1. Install the Vercel CLI or link your Vercel account to GitHub.
2. Under [Vercel Dashboard](https://vercel.com/), click **Add New Project** and import your GitHub repository.
3. Configure project settings:
   - **Root Directory**: `frontend`
   - **Framework Preset**: `Vite` (automatically detected)
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
   - **Environment Variables**:
     - Add `VITE_API_URL` and set it to your **Live Backend API URL** (e.g. `https://inventory-backend.onrender.com`).
4. Click **Deploy**. Vercel will compile the React app, inject the backend URL, and launch it online.

## 🔒 Business Rules & Business Logic

StockSphere enforces several strict database-level and application-level business constraints:
1. **Uniqueness Constraints**:
   - Product SKUs must be globally unique.
   - Customer emails must be globally unique.
2. **Atomic Inventory Transactions**:
   - Creating an order runs inside a SQL transaction. It locks stock records (`SELECT FOR UPDATE`), checks levels, deducts stock, calculates totals, and logs order items. If any product is short on stock, the entire transaction is rolled back.
   - Cancelling/deleting an order runs inside a SQL transaction. It locks and restores product stock levels, then deletes order receipts.
3. **Data Range Sanitization**:
   - Product stock quantity cannot be negative.
   - Product price cannot be negative.
   - Order item quantity ordered must be greater than zero.
